## 2025-03-09 - Avoid calling setState during build and redundant provider lookups in Flutter stateful widgets
**Learning:** Invoking `setState()` during `build()` schedules unnecessary re-render frames and violates Flutter lifecycle expectations. Additionally, evaluating `Provider.of` multiple times within a single `build()` call (e.g. inside ternary statements) adds unnecessary lookup overhead. Moving asset initialization to `didChangeDependencies()` and computing derived state directly during `build()` avoids frame drops and extra build cycles.
**Action:** When calculating derived state inside `build()`, set variables directly instead of wrapping in `setState()`, move asset/marker loading to `didChangeDependencies()`, and cache `Provider.of` instances in local variables.
